## Objective / Summary

Wire the frontend to real backend endpoints, consume the new `AuthResult` shape (`access_token`, `refresh_token`, `user: { id, email, role }`), implement a refresh-with-retry mechanism on 401, and handle shop rehydration after every login so users are redirected correctly.

Previously all API functions in `auth.api.ts` and `shop.api.ts` were mocked. The auth store did not persist a refresh token, logout was synchronous and did not call the backend, and the Axios client had no 401 handling.

## Scope

### In Scope

- Update `AuthResponse` type to match new `AuthResult` shape from backend
- Remove `name` from `User` type (field does not exist on the backend entity)
- Add `ApiResponse<T>` generic wrapper type
- Add `updatedAt: string` to `Shop` type
- Replace all mocked API functions with real Axios calls
- Add `refreshTokens(refreshToken)` and `logoutApi(refreshToken)` API functions
- Add request interceptor: attach `Authorization: Bearer <access_token>` from `localStorage`
- Add 401 response interceptor: silent refresh → retry original request once → redirect to `/login` on second failure
- Add `refreshToken` state to auth store (persisted to `localStorage`)
- Make `logout()` async: call `POST /auth/logout` before clearing state
- After `loginWithEmail` and `loginWithGoogle`: call `GET /shops/mine` and hydrate the shop store
- Add `setShop(shop)` action to shop store
- Add `useEffect` on `DashboardPage` calling `GET /dashboard` on mount (silent auth verification)
- Fix stale closure in `redirectAfterLogin` in `LoginPage` — read live Zustand state with `useShopStore.getState()`
- Apply same smart redirect (dashboard vs onboarding) on Google OAuth path in `RegisterPage`

### Out of Scope

- `name` field on the `User` type (deferred to a separate task)
- Any changes to the router guards or route structure
- Unit tests

## Acceptance Criteria

- [x] `POST /auth/register` response is consumed; `access_token`, `refresh_token`, and `user` are stored correctly
- [x] `POST /auth/login` response is consumed; same store hydration
- [x] `POST /auth/google` response is consumed; same store hydration
- [x] After login, `GET /shops/mine` is called and `shop` state is populated if the user already owns a shop
- [x] A `401` on any protected request triggers a silent `POST /auth/refresh` and retries the original request once; redirects to `/login` only if the refresh also fails
- [x] `POST /auth/logout` is called with the stored refresh token before auth state is cleared
- [x] `GET /dashboard` is called on `DashboardPage` mount; a `401` triggers the refresh-retry flow
- [x] Logging in with Google as an existing user with a shop navigates to `/dashboard` instead of `/onboarding/shop`
- [x] Registering / logging in with Google from `RegisterPage` also checks for an existing shop before navigating
- [x] `npx tsc --noEmit` passes with zero errors
